# Decisions

Format: `D-n` · date · decision · why. The owner was away and could not answer questions, so each unclear choice took the safest, simplest option that meets the brief.

- **D-1 · 2026-11-04 · The small "Leaders: notes" PR is left OPEN, not merged.** The owner first asked for that PR to be merged on green tests, then sent the unattended-build brief with "NEVER merge anything". The newer, stricter rule wins. The PR is opened after its tests pass and stays open for review.
- **D-2 · The original brief is not in this session's saved transcript.** Only the unattended-build brief (which restates the games' requirements in detail) was available. Work follows that brief. Anything the original brief said beyond it is listed under "Leaders must check" in MORNING-SUMMARY.md.
- **D-3 · Branch plan.** `integration/shared` (docs, shared systems, vendored Phaser) → `integration/veil` and `integration/room214` branch from it. Agent work happens on `agent/<role>-<task>` branches or on the integration branches directly when there is one writer. Nothing is merged to `main` by this build. The older `claude/the-veil-ch1` WIP branch is left untouched; its good ideas are ported, not rebased (it predates the shared framework and has no variants).
- **D-3b · No history rewriting.** Local worktrees live in `.wt/` (git-excluded) so the main checkout is never switched while tests run.
- **D-4 · Phaser 3.90.0, one shared copy.** Verified from the npm tarball (checksum in `games-shared/vendor/PHASER-VERSION.md`). The WIP branch's `phaser.min.js` was an unverified different build, so it is not reused. One copy in `games-shared/vendor/` serves both games (cached once by the browser).
- **D-5 · No build step.** Plain classic scripts and a single `window.HOG` namespace, matching the existing games (no bundler, no modules). Keeps GitHub Pages deployment trivial and every file readable.
- **D-6 · No image or audio files.** All art is generated procedurally (Phaser Graphics/canvas textures) and all sound is synthesized with WebAudio. Zero third-party assets, tiny download, nothing to license, and every audio cue has a caption by construction.
- **D-7 · Reuse existing shared helpers.** `assets/js/ho-variant.js` (HOV: hash, seeded rng, shuffle, case codes) and `assets/js/ho-track.js` (GoatCounter events) are loaded as-is. New GoatCounter event names must be added to the whitelist in `ho-track.js`, which is an existing file, so that one-line change goes in the final shared PR. Until then unknown events are silently ignored (safe).
- **D-8 · Tests for the new games live in `tests/new-games/`** and run with their own commands. They are NOT added to `tests/smoke.mjs` (existing suite untouched) until the final PR. Each has a run line in `docs/agents/TASKS.md`.
- **D-9 · Saves.** One localStorage key per game and variant slot via `HOV.slot`: `ho-veil`, `ho-veil_c2` … and `ho-room214`, `ho-room214_c2` …. Settings (mute, volume, low intensity, text size) are per device in `ho-veil_set` / `ho-room214_set`. Export/import is strict whitelist validation (see CONTRACTS.md).
- **D-10 · Failure in Room 214 is "caught and returned to a checkpoint".** No death, blood or injury is ever shown or described.
- **D-11 · Real history.** Nothing in either game is marked "Real history" unless verified by web search with a source in a code comment. Default label everywhere is "Game material".
